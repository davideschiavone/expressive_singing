# Expressive Singing — Project Guide

Static bilingual (FR/EN) website for the Expressive Singing association/company in Geneva.
Plain HTML + CSS + vanilla JS, served as-is (GitHub Pages). **French is the primary language**
(root URLs, `x-default`); English pages live in `en/` and are generated by `tools/build.py`.

## Structure
- One `.html` file per page at the root, in French (index, cours-de-chant-geneve, classes, association, company, events, retreats, blog, contact, booking-success). These are the **source of truth**.
- `en/*.html` — GENERATED English copies. Never edit them by hand.
- `tools/build.py` — regenerates `en/` and `sitemap.xml`. **Run `python3 tools/build.py` after every page edit** and commit its output with the change.
- `booking.html` — unlinked English prototype form, `noindex`, not translated.
- `style.css` — all styling, with CSS variables defined in `:root`.
- `main.js` — nav, hamburger, fade-in, form handling (reads the page language from `<html lang>`).
- `images/` — local assets (team photos, community photos, posters, logo).

## Conventions
- **Bilingual text:** every user-facing string carries `data-en` and `data-fr` attributes, and the element's text in the root page is the French string. Elements with `data-en`/`data-fr` must contain plain text only (wrap mixed content in `<span>`s). `tools/build.py` writes the `data-en` text into the `en/` copy and fails loudly if text and attribute disagree.
- **Other translated attributes:** `data-alt-en`/`data-alt-fr` (img alt, always descriptive French alt text), `data-placeholder-en/-fr`, and `data-en-<attr>` for any attribute that differs in English (`data-en-href`, `data-en-content` on meta tags, `data-en-src`...). Relative asset URLs are rewritten to `../` automatically.
- **Language button** (`#langBtn`): a link to the other language version that shows the CURRENT language — `FR` on French pages (links to `en/<page>`), `EN` on English pages.
- **Head of every page:** French `<title>`/description with English in `data-en`/`data-en-content`, canonical + hreflang `fr`/`en`/`x-default` (= FR), the shared `MusicSchool` JSON-LD. JSON-LD that must match visible text per language (e.g. `FAQPage`) uses `data-ld-lang="fr"` and a `type="text/plain" data-ld-lang="en"` twin.
- **NAP (local SEO):** name, address and phone must be identical everywhere and match the Google Business profile: `Expressive Singing`, `Rue des Grottes 28, 1201 Genève`, `+41 76 266 44 15` (lessons by appointment). The footer and the JSON-LD carry them on every page.
- Use the existing CSS variables and component classes (`.content-section`, `.two-col`, `.value-card`, `.btn`, etc.) rather than ad-hoc styles.
- No emoji in the UI (decorative emoji were intentionally removed; functional `✓` markers are allowed).

## Rules
- **Commit after every task.** When a task is finished, run `git add -A && git commit` with a concise, descriptive message before considering it done. One commit per task.
- **Always align repeated UI.** Whenever creating or editing cards/grids or any repeated component (class cards, event cards, membership cards, payment cards, etc.), make them visually consistent: equal card heights, headers/titles starting at the same height (reserve space with `min-height` for 1- vs 2-line titles), fact rows and dividers aligned across cards, and prices/buttons/footers anchored to the same baseline (`margin-top: auto`). Give buttons a fixed `min-height` so 1-line and 2-line labels match (matters for FR, whose labels often wrap). Then **render the page with headless Chromium and visually verify the alignment** before considering the task done.
- **Always provide real EN and FR copy.** Never put the same French (or English) string in both `data-en` and `data-fr`. Proper nouns/event names that don't translate may stay identical, but translate everything else (city names, "shows"/"représentations", etc.).
